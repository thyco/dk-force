# DK Force Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce `DKForce`, a personal Death Knight addon derived from DK Assist Community, carrying eight wanted features and — above all — shipping the working Stand In Death and Decay reminder unchanged.

**Architecture:** Strip-down fork. The working `DKAssist/` tree is copied and renamed, unwanted features are deleted one atomic feature at a time, and Blightfall's icon mode is ported from upstream v2.0.0 last. Risk is deliberately concentrated in deletions of unwanted code; the Stand In Death and Decay subsystem is touched only by two named edits, in the second-to-last deletion task.

**Tech Stack:** Lua 5.1 (WoW runtime), LibStub, LibCustomGlow-1.0, WoW Retail interface 120100. `luac` 5.5 is used host-side for syntax checking only.

**Spec:** `docs/superpowers/specs/2026-08-29-dk-force-design.md`

## Global Constraints

- Addon folder `DKForce/`, manifest `DKForce.toc`, title `DK Force`, SavedVariables `DKForceDB`, slash command `/dkf`.
- `## Interface: 120100`. Do not change the interface version.
- The string `DKAssist` must not survive anywhere in `DKForce/` outside `Libs/` and the license/attribution lines.
- MIT license preserved, with attribution to ZachoWOW (original DK Assist) and the community fork lineage.
- `Libs/LibStub/` and `Libs/LibCustomGlow-1.0/` are vendored and must never be edited.
- Never edit the Stand In Death and Decay subsystem except via the two edits named in Task 9.
- Source of truth for all "current" line numbers is `/Users/collogt/Work/Projects/dk-assist-community/DKAssist/`. Line numbers shift as tasks delete code — always re-locate by symbol name, never trust a stale line number.

## Testing note — read before Task 1

WoW addons have no unit-test framework, and there is no WoW installation on this
machine. The test cycle for this plan is therefore two-layered:

1. **Automated, every task:** `./verify.sh` — syntax-checks every Lua file,
   checks TOC/disk agreement, checks for stale `DKAssist` identifiers, and
   greps for dangling references to symbols the plan has deleted. Built in
   Task 1. This catches the overwhelming majority of deletion mistakes.
2. **Manual, batched:** in-game `/reload` checks. These are performed by the
   user, not the agent. They are batched at Tasks 1, 7, 9, 10 and 12 rather
   than run after every task.

A task is complete when `./verify.sh` passes. Tasks carrying a manual check are
marked **MANUAL GATE** and must stop for the user.

## Commit policy

This repository's owner commits by hand. **Do not run `git commit`.** Each task
ends by staging its files with `git add` and printing the suggested commit
command for the user to run.

- [ ] **Step 5: Rename every identifier**

Order matters: rename the longest strings first so shorter ones do not corrupt
them. `DKAssistDB` must be rewritten before `DKAssist`.

**Three case variants exist and all three must be handled** — a case-sensitive
pass over `DKAssist` alone misses two of them, and both survivors break the
coexistence requirement:

| Variant | Where | Why it matters |
|---|---|---|
| `DKAssist` | throughout | the obvious one |
| `_dkassist` | ~25 sites in `Config.lua` (`_dkassistOriginalNormal`, `_dkassistOriginalTextures`, …) | these are fields written onto **Blizzard's own button and slider frames**. If DK Assist is also loaded, both addons write the same field on the same shared frame and corrupt each other's texture save/restore. |
| `DKASSIST` | `SLASH_DKASSIST1/2`, `SlashCmdList["DKASSIST"]` | two addons registering the same `SlashCmdList` key collide outright. |

The final `grep` is case-insensitive precisely to catch all three.

```bash
cd /Users/collogt/Work/Projects/dk-force/DKForce
FILES=$(find . -name '*.lua' -not -path './Libs/*')
sed -i '' \
  -e 's/DKAssistDB/DKForceDB/g' \
  -e 's/DKAssist_AddonCompartment/DKForce_AddonCompartment/g' \
  -e 's/_dkAssistWanted/_dkForceWanted/g' \
  -e 's/_dkassist/_dkforce/g' \
  -e 's/DKASSIST/DKFORCE/g' \
  -e 's/DKAssist/DKForce/g' \
  -e 's/DK Assist/DK Force/g' \
  $FILES
grep -rniE "dkassist|dk assist" $FILES | head -20
```

- [ ] **Step 7: Write the verification harness**

```bash
cd /Users/collogt/Work/Projects/dk-force
cat > verify.sh <<'SH'
#!/usr/bin/env bash
# DK Force verification gate.  Run from the repository root.
set -uo pipefail
cd "$(dirname "$0")"
ADDON=DKForce
FAIL=0
say() { printf '%-46s %s\n' "$1" "$2"; }

# 1. Syntax-check every addon Lua file (vendored Libs are never edited).
while IFS= read -r f; do
  if out=$(luac -p "$f" 2>&1); then
    say "syntax  $f" "OK"
  else
    say "syntax  $f" "FAIL"; echo "$out"; FAIL=1
  fi
done < <(find "$ADDON" -name '*.lua' -not -path "$ADDON/Libs/*" | sort)

# 2. Every file the TOC lists must exist.
while IFS= read -r line; do
  line=$(printf '%s' "$line" | tr -d '\r')
  case "$line" in ''|'#'*) continue;; esac
  if [ ! -f "$ADDON/$line" ]; then say "toc lists missing file" "$line"; FAIL=1; fi
done < "$ADDON/$ADDON.toc"

# 3. Every addon Lua file must be listed in the TOC (an unlisted file never loads).
while IFS= read -r f; do
  rel=${f#"$ADDON/"}
  if ! grep -qxF "$rel" "$ADDON/$ADDON.toc"; then say "file not listed in toc" "$rel"; FAIL=1; fi
done < <(find "$ADDON" -name '*.lua' -not -path "$ADDON/Libs/*" | sort)

# 4. No stale DKAssist identifiers outside Libs and attribution lines.
stale=$(grep -rniE "dkassist|dk assist" "$ADDON" --include='*.lua' --include='*.toc' 2>/dev/null \
        | grep -v "/Libs/" | grep -vi "originally\|attribution\|derived from\|ZachoWOW")
if [ -n "$stale" ]; then say "stale DKAssist identifiers (any case)" "FAIL"; echo "$stale"; FAIL=1
else say "stale DKAssist identifiers (any case)" "OK"; fi

# 5. Dangling references to deleted symbols.
if [ -f removed-symbols.txt ]; then
  dangling=0
  while IFS= read -r sym; do
    sym=$(printf '%s' "$sym" | tr -d '\r')
    case "$sym" in ''|'#'*) continue;; esac
    hits=$(grep -rn --include='*.lua' -w -- "$sym" "$ADDON" 2>/dev/null | grep -v "/Libs/")
    if [ -n "$hits" ]; then say "dangling symbol" "$sym"; echo "$hits"; dangling=1; FAIL=1; fi
  done < removed-symbols.txt
  [ $dangling -eq 0 ] && say "removed-symbol check" "OK"
fi

if [ $FAIL -eq 0 ]; then say "RESULT" "PASS"; else say "RESULT" "FAIL"; fi
exit $FAIL
SH
chmod +x verify.sh
printf '# Symbols deleted by this plan. verify.sh fails if any still appear in DKForce/.\n' > removed-symbols.txt
```
